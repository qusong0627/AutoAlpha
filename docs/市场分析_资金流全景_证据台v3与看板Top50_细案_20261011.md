### 9.2 热门三体系与 `hot_type`（后端 `quantdb_snapshot.py` / `quantdb_feed.py` / `router.py`）

- **实锤的口径缺陷**：`/tags/stats` 原实现 = `GROUP BY sector_name, sector_type ORDER BY n DESC LIMIT ?` 全局混合 top-N。
  直查 `latest.db`：全局 top-100 = 概念 89 + 地区 7 + 行业二级 4 + **行业一级 0**——成分数大的体系把
  行业一级整类挤空，前端放大 limit 无解。修复：新增 `hot_type` 查询参数**单体系过滤**
  （SQL 与 DataFrame 两条分支都先按 `sector_type` 过滤再 top-N）；缺省仍为全局混合（向后兼容）。
  缓存键带 `hot_type`（`tag_stats_{limit}_{hot_type or 'all'}`），三体系互不串味。
- 实测单体系 top-18 三体系均存在：行业一级 48 个板块 / 行业二级 80 / 概念 422。
- 前端 `TagBrowserStrip.tsx`：`SET_ORDER = [industry2, industry1, concept]`（与工具栏体系组同序）；
  `hotBySet`/`hotErrBySet` 进程内缓存（已有缓存或已失败即早退）；失败只隐去热门区并给「重试」，
  绝不拦主路径。

### 9.3 搜索两路并行与渲染解耦（`TagBrowserStrip.tsx`）

- 输入非代码形态 → 防抖 200ms 后两路并行：`getTagMatches(q)` 与
  `stockTerminalService.getStockList({ q, page:1, page_size:8 })`；`matchSeq` 序号守卫丢弃陈旧响应；
  `searching/searchingStock`、`searchErr/stockErr` 完全独立。
- **渲染按路就绪**（v6 探针抓到的时序缺陷）：初版以 `searchPending = searching || searchingStock`

## 10. v7 增补（用户第五批实机走查反馈，2026-10-12 落）

### 10.1 反馈与处置

用户原文：「资金流全景 如果检索的个股跳转时候 成分贡献榜（窗口净额 · 点击下钻个股）
选中一下，不然也不知道是哪个板块的。板块都没问题的、板块的话也是要选中第一的个股出来
最右侧。」→ 两条要求：

1. **检索个股跳转** → 成分贡献榜自动定位到该股所属板块并**选中高亮该股行**（否则不知道它属于哪个板块）；
2. **板块跳转** → 自动选中该板块**首位成分股**（|净额| 降序第一行），其个股卡出现在**最右侧**。

### 10.2 机制设计：三类入口 × 两种行为（`FlowPanoramaPanel.tsx`）

| 入口 | 行为 |
|------|------|
| 板块跳转（板块榜行/桑基板块节点/热门 chip/搜索板块候选/证据命中榜） | `selectSector(name)`（默认 `autoPick=true`）→ 明细加载完成后自动下钻 `members[0]`（开个股卡 + 行高亮） |
| 个股打开（融合条个股 chip/桑基个股节点/focusSymbol/成分榜行点击） | `handleSelectStock` → `resolveStockSectors` 按归因定位所属板块（见 10.4） |
| 个股卡内「归因回板块」/因子板行业 chip | `handleCardNavigateSector`（`autoPick:false`）→ 只切板块明细，**保持当前个股锚点**并高亮其行 |

- `autoPickFirstRef`：由 `selectSector` 置位，明细 effect **在加载发起的同帧消费一次**
  （`const autoPick = ref.current; ref.current = false;`）——期间触发的新加载各自取值，seq 守卫
  丢弃晚到者；404/失败路径不残留标志。初始「默认选中排名第一板块」不置位（非跳转，不开卡，
  避免每次进页面/换周期都弹卡）。
- 高亮：`highlightSymbol` 面板级状态 = 当前个股卡个股（归一化前缀式）；`handleCloseStock` 清除。

### 10.3 成分贡献榜选中行（`SectorFlowWorkbench.tsx`）

- `SectorDetailPanel` 加 `highlightSymbol?: string | null` prop；匹配行：
  `aria-current="true"` + `bg-purple-50/90 ring-1 ring-inset ring-purple-300/70`（悬停态仍生效）；
  `ref` 挂匹配行，`[highlightSymbol, detail]` 变化时 `scrollIntoView({ block: 'nearest' })`
  （top30 行在 340px 滚动区内自动滚入可视区）。
- 卡片取数完成回调：`StockFlowDetailCard` 加 `onDetailLoaded?: (d) => void`，经 **ref 镜像**调用
  （父组件每次渲染都传新闭包，不能进 fetch effect deps）。

### 10.4 检索个股 → 板块定位（`resolveStockSectors`）

- 守卫①：`normalizeStockCode(d.symbol) !== normalizeStockCode(selectedStock.symbol)` → 陈旧响应丢弃。
  **归一化不可省**：融合条个股 chip 的 symbol 来自 `/stock-terminal/list`（**后缀式** `600519.SH`），
  而 `/money-flow/stock` 响应 `d.symbol` 是后端归一化**前缀式** `SH600519`——裸串比较会把每次
  检索都误判为陈旧响应，定位静默失效（v7 探针实锤抓出）。`handleSelectStock` 入口即归一化
  （`normalizeStockCode`，`electron/src/utils/portfolioUtils.ts`），选中行/卡片全链前缀式。
- 守卫②（点行开卡不误导航）：该股已在当前明细 `members` 内 → 只高亮不切板块。
- 归因回退链：`sector_set === 当前体系` → `industry2` → `industry1` → 任一有体系项；
  命中即 `setSectorSet`（不同体系先切）+ `selectSector(pick.name, { autoPick:false })`；
  同名板块不重取。
- **数据事实（回退链的真实用例）**：行业二级税目（80 板块）**无酒类成分**——贵州茅台在
  `fetch_sector_members()` 里没有二级行业行（行业二级覆盖 4144/5220≈79.5%），归因只有
  行业一级「酿酒」+ 概念 + 地区。检索「茅台」→ 页面体系自动切到**行业一级**并定位「酿酒」
  （1/36），茅台行选中——诚实呈现其真实归属，不伪造二级板块。
