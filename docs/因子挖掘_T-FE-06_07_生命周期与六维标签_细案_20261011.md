## 三、设计决策（D1–D12）

### D1 注册中心载体 = `rd_agent_factors.metadata_json` 扩展键，不建新表

新键三组：`tags`（六维）、`lifecycle`（显式状态覆盖 + last_eval 快照）、`dependencies`（表达式要素 + code_fp）。
否掉的备选：新表 `factor_registry`（与 factor_id 主键 1:1，纯增加 join 与迁移面）；新列（ALTER TABLE 触及 OSS 存量升级链，JSONB 免迁移）。

### D2 六维标签 = 读时派生为主 + 写侧补源，不强制回填存量

- **纯函数单源**：`backend/shared/factor_tags.py` → `derive_tags(factor_row) -> dict`。shared 无服务依赖，api/engine/scripts 三面可 import。
- 六维取值：
  - `data_source`：metadata 已有（paper 导入 / statistical runner / rd_agent 框架）→ 读时取 `metadata.source/algorithm` 派生（如 `paper110`/`statistical`/`factorminer`）；缺失标 `unknown`（**不猜**）。
  - `frequency`：平台当前全为日频 → 默认 `daily`；表达式含分钟标记才改（V1 留字段）。
  - `family`：**调用方可传优先**（统计派 metadata.family 已在；FM 侧用分类函数），缺 `unknown`——不引入第二套关键词分类。
  - `transform`：表达式字符串级抽取（函数名序列，去重保序）。
  - `target`：metadata.horizon/best horizon 有则用（`fwd_ret_{h}d`），缺省 `fwd_ret_1d`（平台训练/基准序列的次日收益口径）。
  - `maturity`：**不独立存储**——由 lifecycle 状态派生（见 D5），单一 source of truth。
- 存量 224+ 因子零回填：读时派生 + 缺值诚实 `unknown`。写侧只做两个小补：paper 导入补 `source`、统计派 runner 无改动（family 已有）。

### D3 命名规范（3 条，文档 + 报告级校验）

1. `factor_name` 非空、≤64 字符（存量归一口径 `normalize_factor_name` 已在）。
2. 表达式前缀约定：`fm:` = FM-DSL（`FM_CODE_PREFIX` 单源）；其余 = qlib 中缀/代码。
3. 物化列名唯一入口 `feature_column_name()`（`shared/factor_identity.py:89`），禁止手拼。
执行=registry 报告列出违约清单（不阻塞、不大扫除）；新增注册校验不本批做（避免动 save_factor 写面）。

### D4 依赖图 V1 = 表达式要素 + 下游失配报告（复用既有 code_fp 算法）

- 抽取：`factor_tags.extract_expression_deps(code)` → `{fields: [...], operators: [...], windows: [...]}`。`$name` 字段正则 + 函数调用名 + 调用参数数值（窗口）。**字符串级、无 eval、线性扫描**（比 complexity.py 更保守的字符类，超长输入按不可信设计）。标注边界：fm: 的 AST 级结构面仍在 `structure.py`（T-FM-06），本文口径是要素级，不互相冒充。
- 失配检测：`code_fingerprint(当前 factor_code)` vs 物化 manifest 条目 `code_fp`（**同一函数**，`shared/factor_identity.py:71`）→ `materialize_stale`；下游闭包 = 引用该物化列的 catalog mapping（`qm_training_factor_mapping.source_column`）→ 连带标「上游失配」。物化器自身的重算行为不动（它已有 code_changed 逻辑）；本报告只做**可见性**。
- 因子间边（`variant_of`/基线关系）→ **T-FE-09 同批设计**（那里才有真实需求方）；本批 `dependencies` 只存字段/算子/窗口 + code_fp。

### D5 生命周期状态机（四态 + 派生，显式字段只存覆盖）

- 状态：`experiment`（实验）→ `observing`（观察）→ `active`（在用）→ `downweighted`（退役）。
- **派生规则**（`resolve_state(row, first_completed_run_at, now)`，纯函数）：
  - 无 completed run → `experiment`；
  - 有 completed run 且 `now < blind_until` → `observing`；
  - 有且 `now ≥ blind_until` → `active`；
  - `metadata_json.lifecycle.state` 有**显式覆盖**时优先（`downweighted` 只有评估器写；`restore` = 人工清除覆盖，回到派生）。
- `blind_until = (首个 completed run 的 created_at 若存在，否则 factor.created_at) + 180d`——**存量因子零回填自动获得正确状态**（老因子早已过盲窗 → active）。
- 成熟度映射：experiment→实验、observing→观察、active→在用、downweighted→退役；**「验证中」为展示名**：state==experiment 且最新 validation/回测 run 在跑 → 显示「验证中」（不进状态机，防止与验证子系统耦合出第二个状态源）。
- 状态机不含 `retired` 删除语义：「退役（保留算力）」= downweighted 不删行、不删物化列、不删 run。

### D6 盲窗 = 评估读数的研究员面可见性控制（边界显式）

- 盲窗内（state==observing）：`GET /factors` 与 `/factors/{id}` 响应中 **`lifecycle.last_eval` 数字不返回**（保留 state/blind_until 供倒计时展示）；前端显示「观察中 · 盲窗至 YYYY-MM-DD（OOS 读数解锁）」。全窗回测指标（入库时算的）不属 OOS 面，照常显示。
- **显式边界**：盲窗遮的是**平台评估器产出**（滚动 12m OOS 读数）；用户自主触发回测不受限（OSS 自托管场景；机构版可加「盲窗内禁重跑」——列后续）。
- 评估器自身（运维面）照常记录读数——盲窗是研究员面规则，不是运维面规则；台账/报告在 data 目录（不进 UI）。

### D7 月度评估器判定律（全部纯函数，常量集中于模块）

- 读数：`series_json.dates/ic` → eval 参考日往前 **365 自然日**窗口 → `n_days`（非 null 数）、`icir = mean(ic)/std(ic, ddof=1)`（同 `ic_stats.summarize_ic` 口径）。
- 门控（三态，不可算≠差）：
  - series 最新 date 距参考日 > **60 自然日** → `insufficient(series_stale)`（防静止序列假触发；报告提示重跑回测）；
  - `n_days < 120` → `insufficient(too_few_days)`；
  - 最新 cell 非 completed 或无 series → `insufficient(no_completed_series)`。
- 判定：有效读数且 `icir < 0.2` → 该月末计弱；**连续 3 个月末**均为弱读数 → `downweight_candidate`。任一其他结果（回升 ≥0.2 / insufficient）→ 连击**清零**（理由：降权动作重、回收靠人工，宁可漏判不可误判——细案明文）。
- 盲窗保护：判定动作（写 downweighted）额外门控 `决策月末 ≥ blind_until`；盲窗内即使连击满足 → verdict=`observing_protected`（记录不动作）。
- **回溯自愈**：评估器每次运行对「最新 completed run 的 series」重算最近 K 个月末（默认 4）读数并 upsert 台账（键 `(factor_id, month_end)`，附 run_id）——首跑即能对存量弱因子给出连击判定，缺跑的月份自动补齐；同 series 重算幂等。

### D8 降权执行链（两段式显式动作，发布留人工闸门）

`--apply` 与 `--apply-catalog` **分离**：
1. `--apply`：写 `metadata_json.lifecycle={state:"downweighted", since, reason, evidence:{icir,n_days,streak}, blind_until}`（走 `update_factor_metrics` merge 语义）+ 台账记状态变更。消费面可见性（因子库 chip=退役）。
2. `--apply-catalog`（默认关）：经物化 manifest 找 `factor_id→column`，对引用该列的最新 **published** catalog version 执行 `clone_version_mappings` + `disable_catalog_mappings(draft, [column])` → **待人工发布的草稿**（幂等：同名草稿已含该列 disabled 即跳过）。发布=训练口径闸门，人按。
3. 未物化因子：只走 1。
4. 恢复：人工清除覆盖（管理动作/后续 UI），要恢复训练供给=发布含该列的新版本。
理由：月度调度可先 `--apply` 观察一个周期再开 `--apply-catalog`；自动到「草稿已备」不越发布闸。

## 九、评审处置记录（2026-10-11）

**双评审结论：code-reviewer WARNING（HIGH-1 fail-open、MEDIUM-1 盲窗同日边界、MEDIUM-2 前端防御 + LOW×5）；security-reviewer WARNING（MEDIUM×1 盲窗读数经 `metadata` 出口泄漏链）。全部处置完毕，处置后复验见 §9.6。**

### 9.1 HIGH-1（fail-open）→ fail-closed

问题：`_decorate_factor_rows` 原以单 try 包住 run 台账与验证表两个查询——run 台账失败时静默降级，pending 行（cross-market 回测流不写 `rd_agents.status`，降级下无法证明「无成功回测」）会被派生为「实验」，且读数照常放行（盲窗终点不可证实却可见）。

处置（`alpha_agent.py`）：
- 拆为两个独立 try 互不拖累：run 台账失败置 `run_ledger_degraded=True`（日志注明「生命周期按保守口径装饰」）；验证表失败只关「验证中」展示态。
- 降级时对 `experiment` 且 `status != "completed"` 的行 `lifecycle=None`——证据不足**不作声明**（不冒充「实验」），tags maturity 落 `unknown`；行自带 `status="completed"` 是行内成功证据 → 保留派生。
- 读数可见性收敛为单闸：`show_readings = (not run_ledger_degraded) and lifecycle is not None and state != observing`；不满足时 `last_eval=None`（新 dict，不改原行）。
- 新增 API 装配面测试 `backend/tests/test_alpha_agent_factor_lifecycle_face.py`（5 例：双出口同裁 × 观察/在用、详情端点同裁、run 台账降级 fail-closed、验证表失败只降级展示位；TestClient mini-app + 替身注入，不碰真库）。

### 9.2 security-MEDIUM（盲窗泄漏链）→ 双出口同裁

问题：`metadata_json.lifecycle.last_eval/evidence` 与 `lifecycle` 视图是同源数据的两个出口——旧实现只裁视图字段，元数据出口裸奔（盲窗没盲）。

处置：`factor_lifecycle.py` 新增纯函数 `redact_blind_readings`（剥离 `lifecycle` 下 `{last_eval, evidence}`；返回新 dict、输入不可变；持久层原地保留，脱敏只发生在出口），装配层与视图裁剪同点调用。单测 4 例（剥离+不可变、无 lifecycle 透传、非 Mapping 原样、None→{}）。附带加固：`factor_backtest/store.first_completed_at` 与 `mining_plugins/validation_store.running_factor_ids` docstring 注明「调用方只传已鉴权 factor_id，本函数不做归属过滤」。

### 9.3 MEDIUM-1（盲窗同日边界）→ 保守判保护

问题：`verdict_of` 原判据 `latest_day < blind.date()`——评估月末恰为盲窗终点当日时判「已过」进入降权，与「盲窗未满不裁决」原则相悖。
