# 因子工作台（复刻 factor-lib-demo）设计方案

> 参考：https://fifamy.github.io/factor-lib-demo/ —— 目标是**完整复刻**它的能力，用我们自己的数据
> （QuantDB 四个因子集），前端按现有市场分析/因子报告页的风格改。
>
> 与现有「因子报告页」的关系：报告页回答"这因子好不好"；工作台回答"**拿它去回测/合成会怎样**"，
> 两者共用同一批快照与序列（factor_report.json / factor_series.parquet）。
>
> **落地状态（2026-09-13）**：P1–P4 已完成，落点——
> 数据底座 `build_factor_research.py`（factor_panel.parquet / stock_snapshot.parquet / 三基准），
> 计算层 `backend/services/engine/factor_research/scorecard.py`（区间 KPI/标签/综合分/N 扫描/最优权重），
> 接口 `factor_research/router.py`（含 /optimal-weights 与逐因子阈值合成），
> 前端 `electron/src/features/factor-research/`（左侧分类目录 + 区间选择器 + 五页签；
> 排行榜含中位市值/市值风格/前三行业列与持仓数切换）。
>
> **多数据集（2026-09-14）**：工作台支持 `dataset` 切换——
> `classic`（demo 复刻 82 因子）与 `private`（筛选最终保留清单，五库联合筛选 kept，
> 由 `build_factor_panel_private.py` 构建：外部库按月采样 + 截面打分 + 按全样本 IC 符号定向，
> 31 个 factor_research 因子自经典快照拷贝）。快照管理（状态/一键计算）按数据集分别触发；
> 筛选清单重跑后需重算 private 快照。

## 一、对标的六个能力（逐条对应）

| 参考站能力 | 我们的实现 |
|---|---|
| ① 因子排行榜：综合分 = 有效性(50%)+业绩(50%)，各分项在**全因子截面 z-score** 后加权；点列头排序；勾选带入对比/合成 | 新增 `scorecard.py`：分项 z-score → 综合分；API 返回**全部指标列**（年化/夏普/最大回撤/月度胜率/超额 vs 300·800·500/RankIC/IC_IR…），排序与勾选在前端做 |
| ② 时间区间：全部/近3年/近1年/各年/自定义 | 所有回测类 API 收 `start/end`；区间只影响净值与 KPI 的**重算切片**（月末面板已缓存，切片是毫秒级） |
| ③ 因子标签（2 个）：市场环境 4 类 + 时效 4 类，自动判定 | `scorecard.py::tags()`：沪深300 滚动 3 月涨跌分牛/熊/震荡 → 因子三环境月均超额 z-score 取最高者；时效用近 12 月 RankIC vs 全样本差（±0.012） |
| ④ 单因子回测：月末调仓 top-N 等权、0.2% 双边成本、净值/KPI/基准对比、RankIC/IC_IR、**期末净值 vs N 全扫描**、top-N 股票表（含申万行业/市值/PE/PB/成交额）、行业与市值分布 | `build_factor_panel.py` 缓存**每月末每因子的 top-100 股票与次月收益** → 任意 N（1~100）与任意区间都能立刻重算；股票表用 panel 的月末截面 + `instrument_detail`（申万）+ `valuation`（市值/PE/PB）+ 成交额 |
| ⑤ 多因子对比：多因子 × 多持仓数叠加净值 | 前端在同一张图上叠加多因子曲线（每个因子可选 N），数据来自 ④ 的缓存 |
| ⑥ 多因子合成：权重 + 过滤阈值（z-score）+ top-N；**网格搜索最优权重** | `composite.py`：先在月末截面按阈值过滤，再加权合成打分选 top-N；网格搜索在所选因子上做（非负、和为 1，粗网格 + 逐目标） |

## 二、数据底座：月末面板缓存（关键设计）

参考站所有交互都秒回，是因为它把回测**预计算**成了面板。我们也一样：

```
backend/scripts/build_factor_panel.py
  → <数据集>/report/factor_panel.parquet
     一行 = (因子, 月末日期, 名次 1..100)：symbol / next_ret(次月收益) / 当日因子原始值 / z 分
     ≈ 321 因子 × 70 个月 × 100 = 225 万行（每数据集数十 MB）
  → <数据集>/report/factor_benchmark.parquet
     一行 = (月末日期, 基准)：沪深300 / 中证800 / 中证500 的次月收益（超额口径用）
```

有了它：
- **任意 N（1~100）**：每因子每月取前 N 的均值 = 前缀均值（O(1) 切片）✓
- **任意区间**：按月末日期切片后重算净值/KPI ✓
- **任意基准对比**：与基准月收益相减 ✓
- **最新月末的股票表**：直接读 rank≤N 的行 + 估值/行业/成交额 join ✓
- **成本**：每次调仓按 0.2% 双边在净值里扣（月频 → 每月一次）✓

**成本与口径（写死在报告与页面）**：月末收盘调仓、等权、剔除 ST 与上市不足 60 日、0.2% 双边成本、
基准 = 沪深300（超额同时给中证800/500）。

## 三、评分与标签（scorecard.py）

**综合分**（参考站口径）：
```
有效性 z = mean(z(RankIC 均值), z(IC_IR))
业绩   z = mean(z(年化), z(夏普), z(-最大回撤), z(月度胜率))
综合分 = 0.5 × 有效性 z + 0.5 × 业绩 z        # 全部方向已统一为"越大越好"
```
分项 z-score 在**全因子截面**上算（同一数据集内），因此换数据集分数不可直接比。

**市场环境标签**：沪深300 滚动 3 月收益 > +5% 记牛、< −5% 记熊、其余震荡；
每个因子在各环境的**月均超额**（组合月收益 − 沪深300 月收益）在因子间 z-score，取最高者命名；
三项 z 都 < 0.5 → 全天候型。

**时效标签**：近 12 月 RankIC 均值 − 全样本 RankIC 均值：
> +0.012 近期转强；< −0.012 近期失效；两者都 |RankIC| < 0.01 持续低效；其余长期稳定型。

## 四、API（引擎服务，经 /api/v1/factor-report/workbench/* 转发）

| 端点 | 用途 |
|---|---|
| `GET /workbench/leaderboard?dataset=&start=&end=` | 排行榜（全部指标列 + 标签 + 综合分，含分项 z） |
| `GET /workbench/single?dataset=&factor=&n=&start=&end=` | 单因子：净值曲线、KPI、RankIC/IC_IR、期末净值 vs N（1~100 扫描） |
| `GET /workbench/stocks?dataset=&factor=&n=&date=` | 最新月末 top-N 股票表 + 行业分布 + 市值分布 |
| `POST /workbench/compare` | 多因子 × 多持仓数叠加（批量走 single 的组合切片） |
| `POST /workbench/composite` | 合成回测（权重 + 阈值 + N） |
| `POST /workbench/optimal-weights` | 网格搜索最优权重（目标：夏普 / 年化 / 超额，多目标各给一组） |

## 五、前端（改造现有因子报告页）

顶部：**数据集切换 + 时间区间选择 + 标签筛选**（与参考站一致）；
左侧：**因子目录（按分类树 + 搜索）**，每行显示综合分、两个标签、勾选框；
主区三个页签：
1. **排行榜**（可点列头排序、勾选后"带入对比/合成"）
2. **单因子**（净值/KPI 表/期末净值-持仓数扫描/top-N 股票表/行业与市值分布）
3. **多因子**（对比叠加 + 合成权重与网格搜索）

## 六、分期

- **P1 数据底座**：`build_factor_panel.py`（月末面板 + 基准）—— 四数据集约 10 分钟
- **P2 评分标签**：`scorecard.py`（综合分 + 两类标签）
- **P3 API**：workbench 六个端点
- **P4 前端**：改造成三个页签的工作台
- **P5 验证**：与参考站同口径抽查（如某因子 top5 的区间年化/回撤量级）、页面实测

## 七、边界与诚实说明

- **无 ST/上市日期过滤的数据基础**：ST 判定用 `instrument_detail` 的名称含 "ST"；上市不足 60 日用
  `valuation` 首个出现日期近似 —— 与参考站"非 ST"口径基本一致，细节写进页面注释。
- **因子方向**：统一为"数值越大越好"（负向因子在净值/得分计算时取反），原始因子值仍按原样展示。
- **与训练勾选的关系**：工作台的"综合分/业绩"是训练选因子的**同源依据**（组合构建里已用 ICIR+净收益），
  两边口径都写在各自文档里，避免"报告说好用、训练选的是另一批"。
