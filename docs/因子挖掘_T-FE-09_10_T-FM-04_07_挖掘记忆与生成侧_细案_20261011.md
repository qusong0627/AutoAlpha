## 1. T-FE-09 统计派变体残差台账（编辑模因记忆，统计侧先行版）

### 1.1 范围（对齐台账 L109）

每个「家族 × 窗口/变换」变体记录**对父本（基线）的残差 IC**（同窗同池），跨 run 累积到 JSON 台账；置信门控（样本天数不足不给结论）；非对称否决（高置信失败变体进冷却名单）；统计学评估入口读冷却名单（不再重算）。LLM 侧编辑模因（父子 diff 粒度）随 T-FM-04 注入段呈现（本任务在台账中记录结构，不强行复用）。

### 1.2 决策项

**D1 台账形态 = JSON 单文件 + flock + 原子写（仿 `factor_lifecycle` 先例）**
- 落点 `data/factor_variants/variant_ledger.json`（`data/` 为指向 `/media/zbox/data/quantmind` 的符号链接；容器内 `/data` 挂载同一卷，docker-compose :435）。
- 路径解析 `variant_ledger.default_ledger_path()`：env `QM_VARIANT_LEDGER_PATH` 显式覆盖 → else 硬默认 `/data/factor_variants/variant_ledger.json`（容器内即数据卷；与 `mining_pool_rebuild` 等运维面同款「绝对路径 + env 覆盖」形态）。**宿主侧跑 runner 必须显式设 env**——硬默认单落点防「宿主写散落目录、容器读不到」的 split-brain；不采用 `QM_QUANTDB_DATA_DIR` 中间级（其语义是 QuantDB 数据集专属根，台账不是其数据）。〔修订于双评审 CR6，2026-10-12：原稿记的三级链与实现不符，以实现为准改文档。〕**不复用** `backend/scripts/factor_registry_report.data_root()`（scripts→services 是反向依赖，照抄解析链不 import）。
- 写入纪律：同目录 `tmp + os.replace` 原子写（照抄 `factor_lifecycle.save_ledger:477-486`）；读侧坏 JSON/缺失**自愈为空骨架不抛**（`load_ledger:459-474`）。
- **并发**：统计派任务可并行（launcher 有 per_user/global 排队），读-改-写必须 `fcntl.flock`（先例 `mining_pool_rebuild.py:143`）。锁粒度 = 整个 load→upsert→decide→save 段。
- `LEDGER_SCHEMA_VERSION = 1`（现网唯一统计派 mining_report.json 是 28 候选旧格式——跨 run 产物无版本管理，台账必须自带版本）。

**D2 父子映射 `BASELINE_BY_KEY`（显式表，附录 A 全 32 键）**
- 语义 = **编辑模因**：父本 → 子变体的编辑类型分四类：`调窗`（窗口链相邻步进）、`换算子`（$volume→$amount）、`加门`（adaptive 族门控于无门控母本）、`矩变换/估计量变换`。
- 形式：显式 per-key 表（不是机械规则），每行一句理由；表在 `variant_ledger.py` 中为**唯一事实源**，测试强制与 `candidates.py` 目录双向一致（所有 key/父本 ∈ `CANDIDATE_BY_KEY`；链无环）。
- 分类：9 个根（无父本、不判）、1 个无母本（`vol_kurt_gate_10d`：池内无 10 日无门控母本 → 不判不臆造）、22 个子变体。
- **根与链中节点不许冷却**（父本保护：冷却父本会掐断其子的控制链）——`decide_cooling` 内机械守卫：出现在映射值集（是任何人的父本）的键一律不冷却。实际可冷却 = 16 个叶子/侧节点。

**D3 残差原语 = `incremental.py` 新增公开函数 `residual_ic_ir`（单基、不做阈值筛选）**
- 现状：`incremental_ic_ir` 的 basis 由 |行列日均 Spearman ρ| ≥ 0.3 筛选（`incremental.py:295`）——家族父子（如 rev5×rev20）ρ 常 < 0.3，会被判 `no_basis` 拿不到残差；`rho={key:1.0}` 注入会污染 `max_basis_abs_corr` 审计字段成假 1.0（侦查报告 §4 两方案对比）。
- 定案：在 `incremental.py` 增公开函数
  `residual_ic_ir(values, basis_values, *, basis_name, fwd_ret, horizon, min_pairs, min_ic_days, min_names) -> IncrementalResult`：
  - 内部复用 `mean_rho_by_column`（单列，真实 ρ 落 `max_basis_abs_corr`，**不伪造**）、`_daily_rank_z`/`_sequential_residual`（私有 API 不出模块）、`ic_stats.daily_ic/summarize_ic`；与 `incremental_ic_ir` 同式同语义。
  - `fwd_ret` **必传**（调用方持全窗帧；None → ValueError，响亮拒绝而非静默降级）。
  - 状态：`ok / insufficient_days / unavailable`（单基无 `no_basis` 概念；basis 列全 NaN 或值域无交集 → `unavailable` 或残差全 NaN → `insufficient_days`，宁缺勿凑）。
  - `incremental_ic_ir` 行为零改动（新函数独立路径 + 回归测试钉死旧入口不变）。

**D4 置信门控常量（可判线 / 高置信线）**
- 判据只在 `status=="ok"` 时给；**有数线** `min_ic_days=DEFAULT_MIN_IC_DAYS`(20) 由 summarize 语义把关；**高置信线** `HIGH_CONF_DAYS = ic_stats.DEFAULT_MIN_VALID_DAYS`(40) 额外要求。
- **失败** = 高置信 ∧ 残差 ICIR < `COOL_ICIR_FLOOR = 0.3`（= T-FE-01 库级增量闸同标尺：对本族父本都过不了库级增量标尺 ⇒ 族内冗余）。
- `no_basis/insufficient_days/unavailable` **永不判失败**（与 lifecycle「不可算永不冒充差」、incremental「宁缺勿凑」同纪律）。
- **abs() 语义澄清**：ICIR 已取绝对值；强负残差 IC = 变体在**反方向**有独立信息（方向由 signal_side 管）→ **不是失败**。仅 `ic_mean` 符号落台账供审计。

**D5 非对称否决（冷却名单）**
- 高置信失败 → 冷却条目 `{variant_key, universe, since, until, evidence{residual_icir, n_days, horizon, ic_mean}, baseline_key}`；`COOLDOWN_DAYS = 90`（TTL 到期自动失效重评）。
- 键控 `(variant_key, universe)`：换池即重评（跨窗/跨池证据迁移是启发式，窗口信息只入证据供审计；TTL 兜底）。
- **解除（lift）**：同一 universe 出现新鲜高置信通过观测（ok ∧ n_days≥40 ∧ icir≥floor）→ 移除冷却条目（否决有泄压阀）。
- 观测累积：`(variant_key, universe, window_start, window_end, run_id)` 为幂等键（同 task 重跑覆盖同一条）；每键保留最近 `MAX_OBSERVATIONS=24` 条。
- 判定用**最新一条观测**；判定 horizon = 该候选本次报告的 `best_horizon`（全 4 horizons 都记录入台账，判定只认 best——在变体表现最好的 horizon 上仍无增量才算失败，winner's curse 方向=偏不冷却，保守侧）。

**D6 读侧挂点 = 引擎评估入口（文档 D12 指定 `engine.py:494` 循环入口）**
- `run_statistical_mining(..., cooled_keys: frozenset[str] = frozenset())`（默认空 → 现有离线测试一字不变）。
- engine 在 `:488` 前构造 `active = tuple(c for c in CANDIDATES if c.key not in cooled_keys)`；**三处循环**（`:494` 主评估 / `:538` 稳定性 / `:559` 草稿拒因）统一迭代 `active`；`emit("evaluate")` 文案同步 active 数。
- 冷却即减少多重检验数（BH-FDR 的 m 随被评集缩减，`:526-528`）——**审计义务**：`cooled_applied` 列表 + 被评候选清单落 mining_report.json 顶部，runner 传 `--no-cooling` 可整池复跑对照。
- 冷却只跳「自己的评估」；若某 active 子变体的父本在 `cooled_keys` 里（跨 universe 不匹配的边界），该子本轮**不判残差**（status=`no_baseline_in_run`，不冷却）——冷却绝不掐断控制链（与 D2 父本保护互为保险）。

**D7 残差计算在引擎内、按父本分组单遍完成（内存纪律）**
- 迭代顺序 = 按父本分组（父本先评）：进入组时保留父本处理后序列（1 条），逐子计算残差后即弃子序列 → 峰值内存 +1 序列。
- 残差输入 = 与主 IC **完全同管线**的处理后序列（过滤+暖机裁剪+中性化、同 in_is 帧、同 fwd 预计算口径——`fwd` dict 在全交易日帧上预算，`:484-485`），全 4 horizons 各算一次（单基残差成本 ≈ 一次 daily_ic 量级）。
- 计算结果经 `MiningResult.variant_observations`（frozen dataclass 元组）回流 runner；`CandidateReport` 每候选增 `variant_of`（父本 key 或 null）与 `variant_residual`（4 horizons 字典，NaN→null 经 `serialize.json_safe`）。
- engine 保持无 IO 可测性：不 import 台账 IO，只 import `variant_ledger` 的映射表与 dataclass。

**D8 runner 接线（`scripts/alpha_agent/run_statistical_mining.py`）**
- 前置：`load_ledger` → `active_cooled_keys(ledger, universe=…, now=…)` → 传 `cooled_keys`（`--no-cooling` 时传空集）。
- 收尾：flock 段内 load → `upsert_observations` → `decide_cooling`（喂 best_horizon 映射与 now）→ `save`；`mining_report.json` 增 `variant_ledger` 块：`{schema_version, cooled_applied, observations_written, cooling_updates, ledger_path}`。
- 台账写失败**不拦任务收尾**（告警 + 报告标注 `variant_ledger.error`；观测数据仍在 mining_report 可审计）——与注入层纪律同精神。

**D9 API（引擎服务）= `GET /api/v1/alpha-agent/variant-ledger`**
- 读台账 JSON，返回**全 32 键骨架**（来自 `BASELINE_BY_KEY` × 目录，含无观测行）+ 每键最新观测 + 观测史（截断）+ 冷却条目；`available:false` 语义 = 台账文件不存在（首跑前）——返回空骨架而非 404。
- 鉴权 = 既有用户态中间件（`routers/alpha_agent` 统一）；只读，无写端点（重置走 CLI，见 D10）。

**D10 运维** = `python -m backend.services.engine.alpha_agent.statistical.variant_ledger`：`--show`（摘要打印）/ `--reset-cooling KEY`（手工解除，flock 下执行）。

- 统计派拒因（T-FM-01 报告的 reject_reason 词表）混入同表（来源标注），供 LLM 侧「这些方向在统计派已被拒」的先验。

**D3 饱和方向标注（统计侧值级去重命中对聚合）**

**D4 注入通道 = 复用 pool_context 文件模式**

- 段内容：`【历史经验·禁区】` 开头，含 ①拒因聚类 top-8（bucket/次数/最近）②饱和方向 top-8（directions + 90 日查重命中数 + 已物化数）③一句纪律「以上为事实统计，方向选择权在你；命中已知饱和方向的提案需要说明差异化理由」。
- 渲染上限：整段 ≤ 60 行 / 约 700 token（超限按 count 截断并在段内标注「已截断」——不静默）。token 成本可观测（任务行已有 token_usage）。
- **失败只告警不拦主链**：组装/写文件失败 → 日志 warning + 跳过该段（任务照常）。
- 仅 `uses_llm` 算法注入（400 carriesDirection 门与 `_build_runner_cmd` 过滤已保证统计派收不到方向通道；本段同界）。

## 3. T-FE-10 生成侧代理模型 + 方向配额

### 3.1 范围（对齐台账 L110）

从历史挖掘 run 特征训轻量模型预估成功率 → 配额选择器分配「全局探索 / 代理引导利用 / 局部变异」预算，避开饱和方向。落 alpha_agent 侧（RD-Agent 外围调度）。

### 3.2 决策项

**D1 代理模型 v1 = 经验贝叶斯平滑成功率 + 饱和惩罚（刻意不引 LightGBM）**
- 理由（写入模块 docstring）：本平台现网挖掘 run 量级为「数十」条，GBM 在此样本量是过拟合剧场；金融级验证求稳，v1 用可解释、可复现、零依赖的平滑估计，函数边界 `proxy_scores(...)` 可整体替换为学得模型（升级路径：run 数 ≥ 500 且标注质量过关后引入，届时评估脚本先行）。
- 公式（常量单源、测试钉数）：
  - 成功率 `p = (n_success + 0.5) / (n_tasks + 1.0)`（Jeffreys 先验；无史 → 0.5/1.0 = 0.5，中性不冒进）。
  - 饱和惩罚 `sat_penalty = min(0.5, dup_hits_90d / 4)`（T-FM-04 数据；缺 → 0，不臆造）。
  - `score = p × (1 − sat_penalty)`。
- 标签：任务终态 `completed` ∧ `factor_count ≥ 1` = success；范围 = **本用户 × 本市场** 全史（与空白度口径同域）。

**D2 配额分配（三档，常量文档化）**
- `QUOTA_EXPLORE=0.3 / QUOTA_EXPLOIT=0.5 / QUOTA_MUTATE=0.2`。
- 候选来源 = 传入方向词表（与 random/selected 同源）；**硬饱和剔除**：`dup_hits_90d ≥ 2` 的方向从三档候选一律剔除（剔除后某档空 → 回退同档全集 + meta 标注 `tier_fallback`）。
- 三档抽取：
  - explore：空白度加权（复用 `direction_sampling.blankness_weights`，口径一字不改）；
  - exploit：`score` 加权 top-K（K=min(6, |候选|)）内抽；
  - mutate：最近成功任务方向集（最近 5 个 success 任务的 direction，去重）均匀抽；集空 → 退 exploit。
- 逐条落 `direction_meta`（**方向抽样凭证语义**，`direction_sampling.py` 头注已列为既有纪律）：
  `{mode:"quota", tier, weighting, seed, picked, candidates[{direction, attempts|score, weight}], scores_snapshot, tier_fallback?}`——复算方按 meta 重放 `Random(seed).choices` 必得同一命中。
- N 方向并行（`/mining/batch`）：按配额比例切名额（floor + 余数给 exploit），每名额走对应档；逐条独立 meta（同 `sample_weighted_directions_n` 纪律）；N ≥ 候选数时直派全集 meta=None（不伪造 seed）。

**D3 集成点（`routers/alpha_agent.py`）**
- `direction_mode` 三值：`"selected"/"random"/"quota"`。quota 分支接在现抽样点（POST /evolve `:1109-1112` 与 batch 同类点），调 `direction_quota.allocate(...)`；其余模式零改动。
- 400 门不变：统计派（非 LLM 算法）收到方向/配额参数仍 400（`alpha_agent.py:1065-1073`、`:1463-1469`——配额不能搭方向通道进统计派）。
- `direction_meta`/seed 不进任务指纹（`task_fingerprint.py` 规范哈希边界已核）——配额决策不改变任务身份，重跑幂等语义不变。
- 读史/打分失败：**不拦任务创建**，退 random 空白度加权 + meta 标注 `quota_fallback`（与 `_read_attempts` 同兜底纪律，绝不假装配额成功）。

**D4 API = `GET /api/v1/alpha-agent/direction-quota?market=CN`**
- 返回打分表（direction/attempts/success/p/dup_hits_90d/score/saturated）+ 建议配额预演（各档将抽的方向集，给定 n=loop_n? 默认 n=3）；纯只读预览。

**D5 前端**
- SettingsPage「挖掘方向」tab：模式三选（`selected/random/quota`，现有 radio 组 `:988-999` 加第三项；**缺省仍 selected**，quota 由用户显式选）；新面板 `DirectionQuotaPanel.tsx`（挂 ExperienceMemoryPanel 之后）：方向打分表（score 条形 + 饱和标记）+ 三档配额条（explore/exploit/mutate）+ 预演方向 chips；缺失显「—」。
- 服务 `services-v2/directionQuotaApi.ts`；`miningDirections.ts` 的 `miningDirectionMode` 类型扩为三值（兼容旧值）。

**D6 边界**：训练脚本不建（升级路径见 D1）；跨用户共享不纳入；exploit top-K 权重细节（softmax vs 线性）取**线性归一**（简单、可复现、可解释）。

### 3.3 验收

- 单测 `test_direction_quota.py`：平滑公式钉数（含空史=0.5）、饱和剔除与回退、三档名额切分（floor+余数）、meta 可重放（同 seed 同命中）、读史失败兜底标注、N≥候选数直派。
