## 二、P2-a 净 IC（成本口径）

- **口径**：完全复用 `statistical/costs.net_rank_ic` 语义——逐评估日，`rank_pct = v.rank(pct=True) ≥ 0.7` 为多头名单；**当日新进**（对比前一评估日名单）从原始前向收益扣 `get_cost_rate()`（双边）后，再与因子 rank 算 RankIC，窗内均值 = `net_ic60`；同窗 `net_win60` / `net_icir60` 同义。首日/断日行为以 `costs.py` 现实现为准（实现时对齐并在注释标明出处）。
- **实现**：`compute_ic_table` 逐日流式维护每 key 的 `prev_long`（内存 O(当日截面)，不存长序列）；新增可选入参 `fwd_ret=None, cost_rate=None`，缺省时行为与现状完全一致（旧单测零扰动）。原始前向收益由 `composite.fwd_rets()`（`close[i+h]/close[i]-1`，h=5）提供——**rank 不可逆，扣费必须发生在 rank 之前**。
- **不进选择闸**（记录决策）：闸仍按 `|IC60|`（gross）——换闸口径属语义变更，须单独授权；本期净 IC 只做**显形**。
- **显形**：因子 item 增 `net_ic60/net_win60/net_icir60`；`eroded = sign(net_ic60) ≠ sign(ic60)`（成本把边缘吃反的硬事实，不发明倍率阈值）；`validation` 块增 `cost_rate` 与实际值来源（env/yaml/默认）。
- **降级**：`get_cost_rate()` 抛错 → 成本取 0.002 常量兜底 + warning（不允许因成本源缺失整体失败）。

## 三、P2-b IC 衰减告警（|IC20|<0.02）

- **口径**：对每个入选因子，取逐日 IC 序列**尾 20 个有效日**，方向对齐（`sgn×IC`，与持有期画像/合成同口径）后：
  - `flipped`：对齐均值 < 0（方向跨窗翻转；与 horizon 口径一致——翻转显形，不抹平）；
  - `weak`：`|对齐均值| < DECAY_MIN_ABS_IC(0.02)`（细案明文触发值）；
  - `insufficient`：有效日 < `DECAY_MIN_DAYS(15)`（20 窗不套 60 窗的 40 日闸，按比例取 15）；
  - `ok`：其余。
- **落点**：因子 item 增 `ic20/win20/decay`；`validation` 增 `decay:{weak:[...], flipped:[...]}` 汇总；builder 日志 `log.warning` 列明因子（运维面可见）。**QQ 推送不在本期**（板内显形 + 日志；后续如需并入既有告警通道另议）。
- **UI**：因子表新增「近 20 日」列（IC20 数值 + 状态 chip：衰减/翻转/样本不足；`—` 语义照旧）。

## 四、P2-c regime 分桶权重（状态化权重）

- **数据源**：`qm_regime_daily` 冻结表，`load_states_sync("CN", since=长窗首日, until=trade_date)`；**不使用** `qm:regime:intraday`（盘中值，与冻结口径混用会出双源）。当前状态 = trade_date 当日行；缺失 → 取 ≤trade_date 最近一行并记录 `state_asof`（透明化滞后）。
- **长窗**：`REGIME_LOOKBACK=250` 交易日（`list_factor_dates` 全量取尾 250），仅对**入选因子**（27±）算逐日对齐 IC 序列（h=5；窗尾留 h 个未评估日，与主链同规）。分桶复用 `regime_buckets.bucket_of` / `is_weak_bucket`。
- **乘子**（保守双档，不做花式阶梯）：
  - 当前状态桶 `n_days ≥ REGIME_MIN_DAYS(15)` 且 `mean_aligned_ic ≤ 0`（即 `is_weak_bucket`）→ `mult = REGIME_WEAK_MULT(0.5)`；
  - 桶存在但非弱 → `mult = 1.0`；
  - 桶空/样本不足（含 F1 的 bear 空桶）→ `mult = 1.0` + `note="insufficient"`。
  - **只降不翻**：绝不做「按 regime 翻方向」（20–250 日样本上翻转 = 过拟合陷阱）。
- **生效**：`w_eff = w × mult`，写入 sel 的 `w`（合成链零改动）；原始值另存 `w_raw`（审计）。payload 每因子增 `w_raw/regime_mult/regime_ic/regime_n`。
- **顶层 `regime` 块**：`{state, state_asof, lookback_days, bucket_n, weak_count, adjusted_count, by_family:{族: {state_ic, n_days, mult}}}`。
- **降级**：DB 不可达 / 表空 / 长窗无状态 → 整块 `null` + warning，乘子全 1.0（板构建**永不因 regime 失败**）。

## 六、P2-e 入选内二次去重（|ρ|≤0.9 席位置换）

- **池**：`select_factors` 出口扩 `info["gated"]`（gated−sel 明细，含降级分支镜像）→ builder 组「族头池」= 对 gated 按 `(lib,group)` 取 |ic60| 头 `FAMILY_CAP`（rd 4）→ 池条数约为入选数×1.5（≈50）。
- **算法**：`order = 族头池按 |ic60| 降序`；`greedy_select(order, provider=panel.__getitem__, top_k=len(sel原), reject=0.9, warn=0.8, min_names=10)`。无相关对时 `kept` 前 top_k = 当前入选（**恒等退化已证**，F5）；同族/跨族递补均不破族 cap。
- **provider 层**：新 `factor_board/dedup.py` 建 `panel: {key: Series(MultiIndex(dt,symbol))}`——逐日逐库读取池内列（复用 `read_selected_frames` 逐日调用，250 日 dedup 只需评估窗 65 日）。内存 ≈50 key × 65 日 ≈ 百 MB 级，可控。
- **显形**：顶层 `dedup` 块 `{n_pool, n_kept, reject, warn, dropped:[{lib,name,matched_key,rho}], warnings:[...]}`；因子 item 增 `max_abs_corr`。UI 质检条一行：「去重：候选池 N → 入选 M（剔 K 高相关，|ρ|≥0.9）」，tooltip 列 dropped 对与 ρ。

- **测试**：`consume.py` 纯函数单测（fake board / 缺 latest / 陈旧板）；`load_pool` 包装单测（fake pool_doc 两代 schema）；集成：**盘外**（非交易时段）触发一轮 tick——`refusing_submitter` 保证一条腿不发，验证 prompt 渲染与 meta 标注含共振标签（不触碰真实交易时段）。
- **验收**：开关开/关两态的行为对照实机日志 + prompt 落盘目检；开关交付态=关。
