# T-FE-02 细案 · K 因子最佳子集（组合 Sharpe 边际贡献选择）

> 台账出处：`docs/因子挖掘_方法论学习与后期优化_20261011.md` §3 P1「T-FE-02」，
> 依据 §1.3（Ross 2026 等权 1/N 与基数约束组合实证）。2026-10-11 侦查定稿，即日实施。

## 一、规格与论文依据

**台账原文**：K 因子最佳子集：按「对组合 Sharpe 的边际贡献」而非单因子 IC 选 10–15 个
（基数约束近似算法）；给因子组合页。交付物 = 组合层工具 + 报告；基准对照等权 1/N。

**§1.3 依据（Ross 2026）与推导出的设计约束**：

| 论文结论 | 本设计对应约束 |
|---|---|
| 15 因子基数约束组合 OOS Sharpe 3.14 ≈ 158 因子稠密基准；lasso 2.74 | 目标函数 = **组合 Sharpe**（二阶矩口径），不是 IC 均值；K 上限取 15 |
| 「按组合 Sharpe 贡献选因子 ≠ 按 alpha 显著性选」 | 贪心每一步换目标函数：**边际贡献**（加入后组合 Sharpe 变化），不是单因子 \|IC\|/\|ICIR\| |
| **等权 1/N 是默认最优**；<1000 交易日别做复杂组合优化 | ① 子集内**等权**，不做 Σ⁻¹μ 二次优化；② 基准必须有等权 1/N；③ 样本 <1000 天时页面明示该结论 |
| 过拟合是头号杀手：样本内/外 IC 比 >3× 大概率过拟合 | 训练/留出时序切分，选择只用训练窗；**train/holdout Sharpe 比值 >3 亮旗标**（披露而非闸） |

## 二、现状与落点

- 现有组合层 `backend/services/engine/factor_report/portfolio.py`：硬门槛 → 相关性去重 →
  \|IC\|×\|ICIR\| 排序取 top-N → `max_icir_weights` 配权。三处共用：`scripts/build_factor_portfolio.py`、
  `GET /api/v1/factor-report/portfolio`、`scripts/apply_factor_selection_to_catalog.py`。
- 数据面 `factor_series.parquet`（每数据集 `report/` 下）：列含 `factor, date, turnover, coverage,
  ls_1..ls_20`。实测规模：l1_l2_factors 321 因子 × 1137 天；rd_mined 102 × 1636。**计算量秒级**。
- `ls_{h}` = Q10−Q1 极值价差（h 日前向，逐日重算的重叠窗）。既有扣费口径见 `_series_stats`：
  `turn_n = 1−(1−clip(日换手,0,1))^h`、`cost_daily = turn_n × round_trip / h`、`gross_daily = |ls|/h`。
- 前端消费点：`FactorPortfolioModal.tsx`（读 `GET /portfolio`，含「重算」按钮走 `recompute=true`）。

## 三、设计决策（每条含理由；被否决的替代方案一并记录）

**D1 新模块 `backend/services/engine/factor_report/best_subset.py`，纯函数；集成点在 `build_portfolio` 内部，
结果作为 payload 附加块 `best_subset`。**
理由：`build_portfolio` 是页面/脚本/目录写入三处的唯一入口，块随 payload 落盘（`factor_portfolio.json`）
自然被页面读到；新模块保持单测友好。
否决：独立脚本/端独立端点——多一套取数与落盘口径，页面还要合并两份数据。

**D2 收益空间 = 带符号净日收益。** 每因子 `r_f(t) = dir_f × ls_h(t)/h − cost_f(t)`，
`dir_f = sign(ic_mean)`（与 payload `direction` 同源）。
- **为什么不能用 `|ls|/h`**：`_series_stats` 取绝对值是为了均值级闸（净收益是否 >0），均值上等价；
  但 **Sharpe 是二阶矩口径**，`|ls|` 把每日负值翻正、抹掉下行波动 → 假 Sharpe。选择引擎必须用带符号序列。
- 成本公式与 `_series_stats` 逐位同口径（`turnover_cost_daily` 抽到 `optimize.py` 收口，`_series_stats`
  改用同一实现 + 冻结旧实现对拍测试钉死）。

**D3 子集内等权（1/N 思想的子集延伸），方向在因子级，不做子集内 Σ⁻¹μ。**
理由：§1.3 明确等权默认最优、别做复杂优化；选择目标已含二阶矩（Sharpe），再把权重自由度推高没有 OOS 证据支持。

**D4 算法 = 贪心前向 + 1-swap 局部改进（基数约束近似算法），全程只在训练窗内跑。**
- 贪心：从空集起步，每步选「使组合 train Sharpe 提升最大」的候选（边际贡献的字面实现），直到 K_max=15；
- swap：对每个 K∈[K_min,K_max] 的贪心前缀做 best-improvement 单换（换入一个候选换出一个成员，
  Sharpe 提升才接受），上限 8 轮；
- 确定性：非随机启发式，同数据同结果（可复现）。
否决：精确组合搜索（C(321,12) 不可能）；模拟退火/随机重启（引入不可复现且收益不匹配场景）。

**D5 时序切分 train 70% / holdout 30%（不洗牌）。选择只看 train 窗；holdout 只用于披露。**
理由：OOS 判据的前提是选择过程看不见留出窗（单测里用「只在 holdout 有效的因子不得入选」钉死）。

**D6 K 选择：K\* = train Sharpe 最大的 K，平票取小 K。** curve 对 K=K_min..K_max 全披露
（train + holdout 两侧），让「加大 K 是否只是过拟合」肉眼可见。K_min=10、K_max=15（台账规格）；
候选不足时 `K_min=min(10, n)`、`K_max=min(15, n)` 退化并如实标注。

**D7 基准对照（同一收益空间、同一窗口）**：① **等权 1/N 全体候选**（通过硬门槛+去重后的 keep 集，各因子方向对齐）；
② **现行规则**（top-N max_icir 权重向量直接复用，`Σw·ls/h − Σ|w|·cost`）；③ 精选子集。
三者在 train/holdout/full 三窗给出 Sharpe。

**D8 过拟合与样本披露（披露而非自动否决）**：`train/holdout Sharpe 比 > 3` 亮 `overfit_warning`
（类比 §1.3 的 3× 判据）；有效样本 <1000 天时 notes 写明「按论文建议以等权 1/N 为默认基准」。
给 `vs_benchmarks.beats_equal_weight / beats_current_rule` 布尔提示（holdout Sharpe 判定；不可算 → null）。
否决：自动否决（把子集藏起来）——这是研究工具，数字并列展示，判断权交用户；否决的哲学与 T-FE-01 soft 起步一致。

**D9 失败语义**：候选 <3、缺列、取数异常 → `available: false` + reason；集成处 try/except 兜底，
**绝不拖垮主 payload**（best_subset 是附加信息块）。因子有效天（train 窗）< 60 的从候选中剔除并计数披露。

**D10 JSON 纪律**：所有数值经 `_clean`（NaN/Inf→None），round 4 位；沿用 `allow_nan=False` 落盘。

## 五、算法伪码

```
R = 净日收益矩阵 (T×N)              # 方向对齐 + 扣费（D2）
train = R[: int(T·0.7)], holdout = R[int(T·0.7):]
sharpe(M, S) = mean(mean_k∈S M[:,k]) / std(mean_k∈S M[:,k]) × √252     # 等权
S = greedy(train, k_max)            # 逐步 argmax Δsharpe，得嵌套前缀 S_10..S_15
for k in k_lo..k_hi:
    S_k = swap_refine(train, S[:k], passes≤8)    # best-improvement 单换
K* = argmax_k sharpe(train, S_k)，平票取小
benchmarks/curve/holdout 全量评估（同一 R 与窗）
```

## 六、验证口径

**单测（TDD 先行，`backend/tests/test_factor_best_subset.py`）**：
1. 灰色金样：小矩阵手算 Sharpe 对拍（含 √252、ddof=0）；
2. 方向对齐：负 ic_mean 因子净值序列符号翻转；方向错配时 Sharpe 显著恶化；
3. 边际贡献≠单因子 IC：构造 B 单因子强但与 A 重复、C 弱而与 A 正交 → 贪心选 C 不选 B；
4. swap 改进：构造贪心陷入局部最优、单换可改善的经典例；断言换后 train Sharpe 严格提升；
5. 无泄露：仅在 holdout 有效的因子不得进入选中集（选择只看 train）；
6. K 规格：K∈[10,15]、平票取小、候选不足退化与 available=false 路径；
7. 基准对照：等权 1/N 与现行规则（带符号权重）在同一合成矩阵上手算对拍；
8. `_series_stats` 重构对拍：与冻结旧实现逐位一致（含 abs/换手 clip 行为）；
9. 集成：`build_portfolio` payload 带 best_subset；注入异常不拖垮主块（mock 抛错 → 主 payload 仍 available）。

**真实数据验收**：`build_factor_portfolio.py` 对 alpha_library / l1_l2_factors / rd_mined 实跑，
报告 K\*、三窗 Sharpe、与等权 1/N、现行规则的对照（数值进交付报告）。

**前端（vitest）**：`FactorPortfolioModal` 渲染 best_subset 块——K\* chip、因子清单、基准小表、
过拟合旗标、样本 <1000 note、Copy JSON 包含 best_subset；块缺失（旧 JSON）时页面不炸。

**回归**：受影响文件集 + 全量（容器，仓库根视角）。

### MEDIUM：`_sharpe` 近常数序列劫持贪心（已修）

（c=0.0037，ulp≈4.34e-19）→ None；对照真实序列非 None。
